# Codex Windows 完成提醒器

## 预览状态与已知限制

当前为受限源码预览，仅提供任务完成和实验性对话选择提醒。权限审批提醒已移除。选择监测需显式启用；元数据来源不依赖当前聊天渲染。本机已确认其他应用前台、同一 Codex 窗口切换其他聊天时可显示选择浮窗，关闭后不重弹；最小化、多窗口和其他版本仍未完整验收。设置确认保存时同步完成/问题两类原生通知开关，不管理审批通知或原生侧栏状态。历史实验不属于可安装功能。

一个面向 Windows Codex 桌面端的托盘提醒工具。任务完成或识别到待回答的结构化选择卡片时，它可以显示置顶、不抢焦点的浮窗。键盘或鼠标按键可关闭浮窗，输入继续传给下层应用。

浮窗在首次显示前定位到前台窗口所在显示器的工作区右上角。选择扫描以约 1 秒启动周期为目标，慢扫描后至少等待 250 毫秒；只有一个扫描工作线程，不并发叠加扫描，实际提醒延迟仍包含扫描和元数据写入耗时。

v1 仅支持 **Windows 上的 Codex 桌面端**，不承诺支持 Codex CLI、WSL、远程会话或服务会话。

## 功能

- 分别设置任务完成和对话选择请求的提醒方式。
- 每类可选择自定义浮窗、Codex 原生通知、两者或关闭。
- 每类分别编辑标题与说明；自定义弹窗可调整宽度、高度及四种颜色，并实时预览。
- 支持临时暂停、持久关闭本插件提醒或卸载。
- 不联网。Hook 只向本机托盘程序传递事件类型和不透明的事件/回合 ID，不保存或发送提示词、命令文本、键盘或鼠标输入。

## 事件支持

- **任务完成：**使用 Codex `Stop` Hook。
- **对话选择/输入：**显式启用后，由隔离扫描器投影当前用户本机 Codex Desktop 会话的请求元数据；按会话/回合/请求 ID 去重，不依赖当前聊天是否显示。跳过问题、选项、答案和普通聊天文本，不根据文字提问猜测，不隐式回退原生通知。

扫描使用已验证的桌面客户端标记，只处理最新回合的明确请求。完整读到提交记录后清理对应会话；部分写入、超时等未知状态不误清。每轮按修改时间优先处理，最多检查 32 个候选、枚举 2048 个文件，有时间预算和子进程看门狗；不承诺大规模历史会话全覆盖。只输出匿名作用域/请求 ID、计数和读取状态，不保存或联网发送记录内容。

新设置默认保留完成和选择的自定义渠道；实验性选择监测默认关闭，需显式启用并重启提醒器。旧设置的完成、选择和外观偏好保留，权限审批字段在后续保存时不再写入。

`Stop` 表示助手当前一轮回复结束，不代表用户的整体任务一定完成。Hook 在当前聊天、当前回合的协议元数据中确认存在尚未全部提交的结构化选择请求时，会丢弃该阶段的自定义完成提醒，不将它排队；关闭选择浮窗不会补弹该阶段的完成提醒。提交选择后最终回复结束仍按原渠道提醒，其他聊天及旧回合的请求不会全局屏蔽完成。

该过滤适配器仅提取工具类型、请求/回合 ID、问题数量、创建成功标记和回复信封内的请求 ID，跳过问题、选项、答案及回复正文。依赖 Hook 的 session_id、turn_id、transcript_path 及当前本机协议记录格式；路径仅限当前 CODEX_HOME 的 sessions，文件上限 32 MiB，解析预算 500 毫秒。字段缺失、格式变化、部分写入或读取不可用时保留原 Stop 完成行为并记录状态，不猜测用户已回答。普通文字提问不被当作结构化选择。

确认保存渠道时，提醒器会备份并同步 Codex 的完成与问题通知开关。权限审批通知、审批策略、原生侧栏蓝点与需要输入提示不由提醒器管理。外部修改原生偏好后需重启 Codex 验证重载。

## 构建

需要 Windows、.NET Framework 4.x 和 Windows PowerShell。

```powershell
.\build.ps1
```

构建会生成 `dist\CodexReminder.exe`、`dist\CodexReminderScanner.exe` 与 `dist\CodexReminderHook.exe`，并运行内置设置/路由自测。

## 安装和更新

尚未发布稳定安装包。构建产物用于源码预览，实际安装前需完成桌面验收。

安全构建及隔离安装测试使用：

```powershell
.\tests\Run-Tests.ps1
```

当前安装脚本仅允许隔离测试目录，普通生产安装仍有桌面验收门槛。隔离安装只注册本工具的 Stop Hook，并清理本工具遗留的 PermissionRequest Hook；保留其他 Hook、原生配置和其他启动项。源码默认构建、安装 Hook 与托盘统一使用 V4 管道，保留当前用户专用的管道访问控制；不再启动 V5。本机更新仍须备份后应用，并确认真实 Hook 与启动项均指向同一安装目录。

重启 Codex，并在提示时审核、信任更新后的 Hook 定义。未审核并信任的 Hook 会被 Codex 跳过。

## 设置

右键托盘图标，选择 **提醒设置…**。设置按 Windows 用户保存到 `%LOCALAPPDATA%\CodexCompletionReminder\settings.json`。

- 全局开关和各事件的提醒渠道控制本插件的自定义浮窗。确认保存时仅同步完成和问题两类原生通知偏好。
- 对话选择页面提供实验监测开关，并说明保存后重启及覆盖限制。
- 临时暂停只持续到程序退出；全局开关会跨重启保存。
- **退出提醒器**只关闭当前进程，不会卸载 Hook，也不阻止下次事件重新启动。要禁用提醒请关闭全局开关；要移除集成请运行卸载脚本。

## 排查提醒未显示

安装器使用显式 PowerShell 调用，并在 JSON 中设置 `commandWindows`。仅写带引号的程序路径会被 PowerShell 当成字符串输出，而不是执行程序。更新 Hook 命令后，请在 Codex 中重新审核并信任变更后的定义。

请从 Windows 文件资源管理器启动提醒器。不要从 Codex 隔离终端重启托盘程序：其窗口可能被启动到 `CodexSandboxDesktop`，用户实际桌面上不会显示它。Hook 检测到该隔离桌面时不会自动启动不可见的提醒器。

排查浮窗意外关闭时，可在退出当前提醒器后使用 `--popup-diagnostics` 启动。该模式仅在本机设置目录的 `popup-lifetime.log` 记录固定显示、关闭原因和输入事件类别，不记录按键、坐标或聊天内容；日志有大小限制，普通启动默认关闭诊断。未标记为模拟输入的事件不代表已证实来自用户硬件。

Hook 在 `%LOCALAPPDATA%\CodexCompletionReminder\hook-status.log` 记录事件类型和通信状态，不记录对话、命令或键鼠内容。`received-Stop` 表示 Hook 被调用，`pipe-written` 只表示事件已写入通信通道，不证明用户看到了浮窗。`pipe-error-UnauthorizedAccessException` 表示通信被权限边界阻止。正常 Hook 仍保留原来的完成语义；未支持的事件不输出审批决定。

在用户自己的 PowerShell 中，可用 `CodexReminderHook.exe --diagnostic` 接收测试事件；此模式在通信失败时返回非零退出码。Codex 隔离工具中的测试可能被拒绝访问，不能以退出码 0 或窗口接口的“可见”状态作为桌面验收依据。

## 卸载

```powershell
.\uninstall.ps1
```

卸载只删除本工具管理的 Hook 和登录启动项，默认保留用户设置。若也要删除设置文件：

```powershell
.\uninstall.ps1 -RemoveSettings
```

```powershell
.\tests\Run-Tests.ps1
```
