# UIA 识别验证记录

日期：2026-10-11。阶段：只读可行性实验，未安装到生产提醒器。

## 方法与隐私范围

使用本机 .NET Framework UIAutomationClient/UIAutomationTypes，和实验性 MSAA 兼容读取路径。仅针对 Codex 应用读取控件类型、固定操作按钮和运行时标识。不读取问题、选项或编辑框值，不自动操作卡片，不保存对话或截图。

系统 UI 操作只用于验证前后台状态，未批准或拒绝任何审批，未由程序改变审批策略。

## 已获得的证据

| 场景 | 结果 | 证据与边界 |
| --- | --- | --- |
| 未回答的真实选择卡片，前台 | 通过识别 | UIA 读取到 2 个单选控件、1 张含跳过/发送按钮的卡片 |
| 同一真实卡片，被资源管理器置前遮挡 | 通过识别 | UIA 仍读取到 2 个单选控件、1 张卡片，无需激活 Codex |
| 连续读取中同一待回答卡片 | 初步通过 | 40 秒读取只有初始状态输出，同一进程内未反复产生新 ID |
| 新的实际选择请求 | 通过识别 | 后续请求仍读取到 1 张卡片；不靠聊天正文判断 |
| MSAA 兼容路径，前台 | 通过识别 | 读取到 1 个有效根、2 个单选控件、1 张卡片；性能尚未达成生产门槛 |
| 无人工审批的直接执行，屏幕已就绪 | 负例与观察一致 | 用户明确反馈没有审批卡片、命令直接执行；控件探测 Windows=1、MinimizedWindows=0、Unknown=false、ApprovalCards=[]。不证明真实审批卡片能被检测 |

连续读取不等于用户处理后的去重/撤销逻辑已经验证，仍需完整状态转换测试。

## 未通过或尚未验证

- 实际请求在 Codex 最小化时，UIA 找到窗口但读取到 0 个单选控件和 0 张卡片。随后探测程序将这种结果标记为 `MinimizedContentUnavailable`/未知，避免误判解决；这仍不能检测最小化期间新出现的请求。
- Windows 界面自动化的窗口切换操作受到“检测到用户操作”和“坐标几何不可用”限制，因此没有完整获得暖启动后最小化/恢复的连续转换证据；不会把失败操作记作成功。
- 用户已同意人工审批测试，并反馈已将当前对话改为请求审批。一次无副作用读取已执行，但未捕获到保持待处理的人工审批卡片。当前回合上下文仍标识为自动审核，下一轮需核验新选择是否已生效。
- 请求回答、跳过、自动撤销后的程序化移除尚未通过完整测试。
- 最小化 MSAA、新请求去重、切换到其他聊天和多窗口覆盖尚未验证。
- 自定义浮窗集成、自动撤销、原生互斥和生产更新尚未开始。

## 当前状态与下一步

生产提醒器、原生设置与桌面副本未被本实验替换。实验代码与生产源码隔离。

安全读取未形成真实人工等待，不反复用同类读取冒充正向审批测试。真实审批正例与最小化门槛仍需解决；若无法可靠识别，按已批准计划报告具体限制，不停用自定义来替代，也不自动启用原生通知。

本轮完整窗口截图/文本请求被自动审批审查拒绝，因为超出仅检查确认控件的授权范围；随后改为控件级只读探测并成功执行，未采集整窗内容。实验审批选择器仅匹配固定的启用批准/拒绝按钮组合，标签仍需在真实人工卡片上验证，尚不能作为生产检测器。
