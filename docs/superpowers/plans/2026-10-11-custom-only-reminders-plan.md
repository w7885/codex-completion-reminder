# 全自定义提醒实施计划

日期：2026-10-11。依据已确认的设计：`../specs/2026-10-11-custom-only-reminders-design.md`。

目标：完成、真实人工审批、结构化对话选择使用可选的自定义浮窗；选择仅自定义时关闭对应原生通知。排除自动审批误报，同一请求只提醒一次，处理后撤销。不得通过关闭自定义或启用原生来替代目标。

执行方式建议：在当前对话由主代理顺序执行，不创建新对话，不使用子代理。先完成验证门槛，再接入生产程序。只修改原源码和本机安装版本；桌面副本不变。

## 1. 建立隔离的只读 UIA 验证程序

- 新建 `experiments/uia-probe/`，代码与生产构建隔离，标明验证用途。
- 使用 .NET Framework 的 UIAutomationClient/UIAutomationTypes，在独立后台线程读取；不注入输入，不点击控件。
- 只定位实际 Codex 应用窗口，避免扫描无关应用。每次重新获取控件结构，不能沿用过时快照。
- 识别已验证的选择卡片组合：单选按钮组、跳过按钮、发送按钮。只取控件类型、必要的固定操作标签、运行时标识；不取问题正文、选项文本或编辑框值。
- 输出仅包含类别、不透明 ID 与检测成功/未知状态，不保存窗口内容。
- 验证真实卡片出现、回答/跳过后消失，普通聊天和历史回答不触发。

完成标准：实际出现/消失状态能重复观察，无法读取时明确报告未知；不误判为已解决。

## 2. 验证人工审批卡片与窗口覆盖范围

- 获取一张真实人工审批卡片，核对其可操作按钮结构；不要依靠原始 PermissionRequest。
- 如测试需要临时改变审核方式，先在测试发生时由用户明确选择，仅使用无副作用的读取测试；不静默切换审批策略，不开启 Full Access。
- 用户批准或取消后，验证实际卡片被移除。验证自动审批时没有相同的人工卡片结构。
- 分别验证当前窗口前台、被其他应用覆盖、最小化、切换聊天和多窗口。
- 对尚未展示的其他聊天卡片，验证是否可观察；无法覆盖时明确记录限制，不能宣称全局可靠。

完成标准：人工审批识别有真实证据，自动审核不产生确认事件。没有达到该门槛则不安装 v0.2，保留现有可运行版本并报告限制。

## 3. 实现只读监测与请求生命周期

- 新增 `src/HumanWaitMonitor.cs`，封装窗口定位与结构化卡片扫描。
- 新增 `src/HumanWaitState.cs`，将状态判断与 UIA 分开，便于测试。
- 只输出已验证的审批/选择类别及不透明请求 ID。未知读数保留已有等待状态。
- 处理新增、仍等待、已解决三个状态。请求关闭后释放去重状态，后续新请求仍提醒。
- 手动关闭浮窗不回答请求；同一请求持续等待时不再重复提醒。
- 监测由明确的用户设置控制；全局关闭、暂停和退出停止读取或展示，不能暗中回退原生。
- 启用时显示实验性识别及兼容范围说明。读取故障不得改变审批或模拟用户响应。

完成标准：生命周期单元测试通过，服务可停止，故障恢复不重弹同一请求。

## 4. 接入浮窗队列与自动撤销

- 修改 `src/Program.cs` 和 `PendingNotificationQueue`，将真实卡片状态接入原有托盘 UI 线程。
- 停止把原始 PermissionRequest 转为确认浮窗；保留其诊断和无审批决定的输出契约。
- 实际等待用户时优先显示“任务需确认”。请求已解决时撤销其提醒，不能留过时浮窗。
- 检查 Stop 与提问卡片的先后顺序，避免用户仍需操作时同时显示相互矛盾的完成提示。不得通过解析回复内容判断。
- 保留完成合并、无焦点抢占、键鼠关闭与输入穿透。

完成标准：真实选择与审批提醒显示并撤销；手动关闭后不重弹；普通完成提醒回归通过。

## 5. 实现四种渠道与原生互斥

- 从 `docs/prototypes/NativeNotificationSettings.cs` 复用经测试的 TOML 修改、备份和失败回滚。
- 不复用旧实验补丁中停用自定义审批/选择的策略。
- 修改 `ReminderSettings.cs` 和 `ReminderSettingsForm.cs`：保留三类自定义选项，加入明确的只读卡片监测开关与说明。
- 完成、审批、选择各自可选仅自定义、仅原生、两者、关闭。
- 仅自定义：关闭对应原生；仅原生：关闭该类自定义并启用原生；两者：均开启；关闭：两者均关闭。
- 只修改用户级 config.toml 的 `[desktop]` 中三个已核实键：
  - `notifications-turn-mode`：`off` 或 `always`。
  - `notifications-permissions-enabled`：布尔值。
  - `notifications-questions-enabled`：布尔值。
- 保留其他配置与 Hook 信任、审批策略；保存失败回滚，并向用户明确说明全局影响及重启要求。
- 复用设置窗口保存/取消按钮布局修复，固定显示全局影响说明。

完成标准：三类自定义选择都可保留，未出现隐式原生回退；配置保留与回滚测试通过，按钮可见。

## 6. 测试与证据整理

- 扩展 `SelfTests.cs`、`tests/Run-Tests.ps1`、`build.ps1`，加入监测组件的引用与状态测试。
- 使用结构化控件/状态样例做单元测试，但明确样例不能代替真实 UI 验收。
- 覆盖同一请求去重、解决撤销、新请求、未知状态、暂停恢复、三类渠道、配置更新事务和审批无决定契约。
- 生成设置窗口离线预览，检查按钮、提示、未启用监测的说明与选项是否完整。
- 在 `docs/validation/` 记录真实 UI 验收、版本、失败与局限；不写入截图正文或用户私密内容。
- 无新增变化或失败时不重复运行全套测试。

完成标准：必要自动测试通过，真实桌面验收逐项记录，未验证项标明；不可用场景不能宣传为已完成。

## 7. 安全更新本机使用版本

- 保存当前程序、用户设置与三个原生通知值的恢复材料。
- 先核实安装操作处于 `Default` 交互桌面，避免再次把托盘程序启动到 CodexSandboxDesktop。
- 仅在前述门槛通过后复制新二进制与设置，更新本机程序；不运行会安装未验证行为的旧实验包。
- 为当前用户按明确偏好选择三类仅自定义；不改成原生或关闭自定义，不降低审批安全设置。
- 对比除三个通知键以外的 Codex 配置，保持桌面项目副本不变。
- 原生配置需要重新加载时，请用户在本轮结束后重启 Codex，不强制关闭当前任务。
- 用真实完成、选择与人工审批事件完成最后验收，不把写入成功当成用户已看见。
- 更新原项目的本地安装包与说明；不推送 GitHub，不发布未经授权的公开 Release。

完成标准：实际使用版本行为符合三类自定义目标，原生仅在用户选择时出现，用户视觉确认通过。

UIA 结构可能随应用版本变化；最小化、其他聊天和读取缓存需要实际验证。真实审批结构尚未完成核验。若无法可靠识别，先报告具体失败与保留可运行版本，不擅自停用用户希望保留的自定义渠道，也不恢复原生来替代。

本计划待审阅后执行。专用 writing-plans 技能在当前技能目录与插件缓存中未找到，计划按已确认设计手工整理。
